## 案例定位

真实 MVP 是"给我自己（和老板）用的研究工作台"；本案例把它翻译成**面向个人投资者的每日情报界面**，核心命题是 JD 里的那句"AI 不确定性的优雅处理"——投资者面对 AI 结论的第一个问题是"凭什么信"，所以每一屏都在回答：**证据可回查、口径可见、不确定就明示**。

## 真实项目资产（面试可出示的底气）

- 独立完成 v0.1 → v0.7 迭代：本地知识库（SQLite + BGE 512 维向量 + 版本/备份）→ 板块事件雷达 → MiMo 事件拆解（证据≤6 篇/2 万字符/日 20 次额度）→ 引文核验 → 采纳/驳回复核流 → v0.7 行情事实层（五种核验状态，未配置不伪造）
- 完整 PRD 链（v0.1/v0.2/v0.5/v0.6）与使用说明、隔离测试（`test_knowledge.py` 等）
- 纪律性设计原则贯穿始终："模型拆分完成≠人工认可""星级=基本面影响强度，不是上涨概率""未映射主题不能强行推荐股票"

## 页面清单（原型/，静态可点击，双端响应式）

| 页 | 文件 | 对应真实功能 | C 端化关键点 |
|---|---|---|---|
| 封面 | [index.html](原型/index.html) | — | 真实资产→界面转译表、30 秒电梯稿 |
| P1 板块雷达 | [radar.html](原型/radar.html) | 板块工作台 v0.6 | 热力卡可视化；未拆解事件明示"不显示利好/利空"；每日额度口径 |

## 面试常见追问预案

| 追问 | 回答要点 |
|---|---|
| "为什么不直接显示 AI 的涨跌预测？" | 系统没有行情回测与复权数据支撑，预测不可验证；不可验证的输出对投资者是负资产。路线图顺序（复核→聚类→主数据→行情验证）本身就是设计决策 |
| "C 端用户会看引文吗？" | 引文卡是"可证伪性"的存在证明——不要求人人点开，但要知道随时能点开（类似安全带）；访谈提纲 H2 会验证这个假设（见念念案例 00 文档） |
| "和同花顺/东财的新闻流差异？" | 它们是"信息更快"，这里是"结论可回查"——每条方向判断都落到原文引文与复核状态上 |
| "演示数据可信吗？" | 页面逐处标注演示数据；真实机制（额度/预算/校验状态）数值取自真实 MVP 的配置上限 |
