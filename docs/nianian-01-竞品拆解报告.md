## 2. 功能全景（板块 × 要点）

### 2.1 豆包 —— 记忆功能面（来自官方记忆 FAQ）

| 板块 | 要点 | 取证 |
|---|---|---|
| 记忆开关 | 设置-记忆，一键开/关；关闭=不再参考也不再更新，但**不删除已有记忆** | 官方FAQ |
| 自动记忆 | 从历史对话由模型"总结提炼"，**有刷新频率周期、非实时**；"模型可能不会记住所有细节" | 官方FAQ |
| 指令记忆 | 对话中说"请记住/忘记××"实时生效 | 官方FAQ |
| 记忆来源 | 仅对话文本（含实时通话语音转文本）；**不含图片/文件/链接/视频画面** | 官方FAQ |
| 记忆管理 | 设置面板逐条查看、左滑删单条、一键删全部 | 官方FAQ |
| 上限与淘汰 | 总量有限，**超限后"最近保存的记忆自动覆盖最早的"（FIFO）** | 官方FAQ |
| 删除生效 | "删除后需一定时间才停止被参考，非实时"；**删除聊天记录 ≠ 删除记忆** | 官方FAQ |

### 2.2 ChatGPT —— 两层记忆与控制

| 板块 | 要点 | 取证 |
|---|---|---|
| Saved Memories | 持久事实（姓名/职业/偏好），自动+显式保存；设置内逐条增删改 | 帮助文档 |
| Reference Chat History | 引用历史对话本身（不落成显式记忆条目），独立开关 | 帮助文档 |
| 关闭≠删除 | 关闭引用后 30 天内从系统删除；关闭 Memory 不清除既有记忆，**需手动删** | 帮助文档 |
| 记忆提示 | 对话中生成"Memory updated"轻提示条 | 公开界面 |

### 2.3 星野 —— 情绪体验面（来自公开拆解长文）

| 板块 | 要点 | 取证 |
|---|---|---|
| 角色卡三层 | 形象（图+描述词→18张图）/ 人设（模板 few-shot）/ 音色（5种按比例混音） | 拆解长文 |
| 对话控制六机制 | 重说 / 回溯（长按回节点，类"遗忘"）/ 记忆 / 重启 / 评价 / 事件簿 | 拆解长文 |
| 事件簿 | 阶段性内容摘要，推测用于应对上下文超长 | 拆解长文 |
| 星念（记忆相片） | 正面图像+背面故事线；**随机性强、不可编辑、与对话主线交融弱** | 拆解长文 |
| 商业化 | 星月卡 + 星钻抽卡（单抽/十连）+ 挂牌交易分成 | 拆解长文/行业报道 |

### 2.4 Replika / Pi —— 海外参照

| 板块 | 要点 | 取证 |
|---|---|---|
| Replika 记忆 | 事实抽取层 + 短期上下文注入 prompt；用户反馈"记忆浅，只记得基本信息，缺乏连续性" | 帮助中心/Reddit/Medium 对比 |
| Replika 强化 | 记对了 → 点赞强化该记忆（有"确认"概念，但无纠错队列） | 帮助中心 |
| Pi 范式 | 无头像、无虚拟形象、不做生产力，纯对话情绪支持；Public Benefit Corporation 定位 | 官网/商店条目 |

## 3. 弱点观察（比功能更值钱的部分）

| # | 弱点（取证） | 对我们的启示 |
|---|---|---|
| W1 | **失忆不可感知**：AI 无法知道自己忘了什么（Deepractice）；上下文压缩造成"两小时默契下一轮消失"（知乎社区） | 记忆要有"褪色/断层"的可视口径——不确定就说不确定 |
| W2 | **记错无法优雅纠正**：ChatGPT 存入错误/creepy 记忆引发不适（Every 专栏、Wired）；用户只能被动删除 | 新记忆先进**待确认队列**，采纳/驳回/修正由用户主导 |
| W3 | **静默丢失**：ChatGPT 后端记忆架构更新后用户积累的上下文静默消失（OpenAI 社区"Catastrophic Failures"帖） | 记忆变更要留**账本**：什么时候记的、改过什么、为何失效 |
| W4 | **FIFO 覆盖 + 删除非实时**：豆包超限自动覆盖最早记忆；删除后"需一定时间才停止被参考" | 记忆淘汰要有**用户可见的规则与优先级**，不悄悄扔 |
| W5 | **黑盒感**：各家只给"记忆条目列表"，无来源（哪次对话）、无置信度、无冲突处理界面 | 每条记忆带**来源引用卡**，可回查原文 |
| W6 | **主动关怀缺失或无节制**：ChatGPT Tasks/Pulse 靠用户自行设定；陪伴类产品无"克制"设计 | 关怀要**有账本、有边界、可关停单一主题** |
| W7 | **心理健康争议**：长期 AI 陪伴或加剧孤独/依赖（人民日报海外版报道研究） | 陪伴体验要内置"健康的节制"叙事，反而成立为差异化 |

**收敛：五家竞品在"记忆的黑盒性"上高度一致——记住什么、为什么、何时会忘、错了怎么办，用户全部不可见。而用户最大的三类抱怨（失忆 W1、记错 W2、失控 W4/W5）全部指向这个空白。这就是本案例的差异化落点。**

## 4. 映射总表（竞品板块 → 处理决策）

> L1 = 复刻对齐 · L2 = 注入我方内核（可验证的信任）· L3 = 独有差异化 · 不做 = 有理由的放弃
> 我方内核盘点：**证据链**（风云汇：引文卡/来源回查）· **复核流**（风云汇：采纳/驳回）· **口径纪律**（风云汇：核验状态角标）· **记忆架构**（森森：分层记忆模块/按需召回/时间衰减打分）· **关怀克制**（森森：偏好主动关怀 + Tasks 式用户设定优先）

| 竞品板块 | 竞品现状 | 我方决策 | 决策理由 |
|---|---|---|---|
| 多轮对话（文本） | 全员标配 | **L1** | 已验证需求，体验不输即可 |
| 记忆：自动提炼 | 豆包/ChatGPT 有，黑盒 | **L2**：自动记忆→"待确认"队列，采纳后方入长期库 | 吃进内核③④：复核流+分层架构 |
| 记忆：指令保存 | "请记住××"实时生效 | **L2**：指令记忆同样落来源卡（可回查是哪句话） | 吃进内核①：证据链 |
| 记忆管理面板 | 条目列表+删除 | **L2→L3**：八模块分组 + 来源引用卡 + 置信度/新鲜度口径角标 | 竞品均无；L3 依赖记忆架构资产 |
| 记忆淘汰（上限/覆盖） | 豆包 FIFO 黑箱 | **L2**：褪色机制可视化——"30天未确认，AI 可能记不准了" | 吃进内核③口径纪律+森森时间衰减 |
| 记忆：引用历史对话 | ChatGPT Reference | **L2**：引用时同步出示出处（点开看原对话片段） | 证据链 |
| 记忆出错/冲突 | 无处理界面 | **L3**：冲突检测卡（新旧说法矛盾→并列呈现待裁决） | 机制积累，短期难抄 |
| 空态/提示词引导 | 豆包示例prompt、星野"灵感"回复 | **L1+微创新**：空态按记忆模块推荐话题（"好久没聊你上周的面试了"） | L1 基础上吃记忆架构 |
| 对话控制（重说/回溯/评价） | 星野六机制 | **L1**（取重说+评价两件） | 陪伴场景已验证；六件太重 |
| 语音对话/音色 | 豆包通话、星野混音 | **不做**（V1） | 原型聚焦记忆体验主线；语音是独立工程量 |
| 角色卡/虚拟形象 | 星野三层、Replika Avatar | **不做** | 定位是"助理"非"扮演"；Pi 已证明无形象路线成立 |
| 星念/抽卡/交易 | 星野游戏化 | **不做** | 与"可信陪伴"定位冲突；作者分析其转化亦弱 |
| 主动关怀 | ChatGPT Tasks 用户自设；陪伴类无 | **L3**：关怀中心=计划+账本+边界（频率上限/免打扰/单主题关停），AI 发起的每条关怀可回查依据 | 关怀有据可查=全新品类点 |
| 情绪支持对话 | Pi 范式 | **L1**：温暖语气规范 + 不确定时诚实降级话术 | Pi 验证过极简情绪路线 |
| 数据主权（导出/暂停） | 各家仅有删除 | **L2**：一键导出全部记忆+来源、暂停记忆不影响历史 | 隐私叙事与产品主张自洽 |
| 订阅商业化 | 星月卡¥12/月等 | **不做**（V1 仅设计页留白） | 作品集阶段展示克制 |

## 5. 结论

竞品把"记得住"做成了卖点，却把"记得可不可信、可不可控"留成了空白——而这恰是用户抱怨最集中、且与我方内核（证据链/复核流/口径纪律/记忆架构）严丝合缝的位置。本案例的打法由此确定：**L1 立住"有记忆的陪伴助理"基本盘，L2/L3 把记忆从黑盒做成"看得见、查得到、管得住"的透明系统。**
